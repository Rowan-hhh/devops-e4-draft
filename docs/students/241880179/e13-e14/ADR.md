# ADR：E13 B1 使用隔离副本和字节哈希完成交叉测试

## 状态

已接受并经本人复核。

## 背景

E13 要求在 E12 已集成系统上消费 A 组当次真实报告，并对旧报告、错误目标和教师未知项目进行测试。教师未知项目不能替代 A/B 真实项目，教师 ZIP 也不应上传到公开仓库。

## 决策

1. 以 A 组固定合并提交、完整 target、job/trace 和原始报告 SHA-256 共同绑定 C1 输入。
2. C2 在隔离副本中分别注入旧报告和错误 target，并要求在修复前拒绝。
3. 将官方 `handoff_a_to_b.py` 和日志扫描器导入课程仓库；B 侧读取 fixed-md 前可选校验 `fixed_report_sha256`。
4. H1-jsmn 只在课程服务器个人目录解压和运行，公开仓库仅归档请求、Patch、验证、重检、哈希和脱敏日志，不归档教师 ZIP 或上游源码。
5. 网络导致的 baseline 失败与镜像重试分别保留，禁止覆盖失败目录或把超时写成成功。

## 结果

C1 成功且最终无 `MISSING`；C2 两种错误输入均在修复前拒绝；H1 五阶段成功，验证接受并通过重检；服务器运行日志扫描未发现疑似密钥。baseline 的官方源超时被如实记录，隔离镜像重试成功。

## E14 B3 补充决策

1. E14 只从已合并且通过 E13 门禁的 `main` 建立个人分支，不以未合并组员分支为基线。
2. A05 和 B 组真实项目使用独立请求和独立输出目录，禁止一方结果代替另一方。
3. 旧 B 项目请求的相对路径不符合 E14 `/course/data` 合约时，保留前置拒绝日志，修正请求后使用新目录重跑，不覆盖失败记录。
4. 验收必须同时满足五阶段身份一致、产物哈希正确、补丁接受、recheck 提交正确和最终无 `MISSING`。
5. 完成后只关闭本人 Compose 项目 `e14-241880179-b3`，不清理共享 Docker 镜像或他人容器。
