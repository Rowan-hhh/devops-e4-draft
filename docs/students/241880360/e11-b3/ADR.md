# ADR：E11 B3 在修复生成前验证契约并保留无写入证据

## 状态与背景

已采用。B2 已完成固定 MD 的正确候选、隔离验证和动态重检；B3 负责异常拒绝及 macro/mixed 扩展。错误输入应在产生修复之前终止，且结果必须可由原始证据复核。

## 决策

1. 复用生产 `pipeline.check_envelope`、`pipeline.load_artifact`，实际构造旧提交、错误 schema、错误 kind、内容变化和失败上游输入，以捕获的 `Failure.code` 记录实际错误；不伪造错误结果。
2. `consume` 先校验内容哈希、外层契约及内部提交，全部通过后才允许调用真实 `patch`。五类异常均在此前终止。
3. 只使用新输出目录，已有目录（包括空目录）拒绝覆盖，输出不允许位于源项目内。核心函数不依赖分支名，分支保护仅在 CLI 入口。
4. 在修复输出目录写入前后取哈希清单，源项目也保存前后完整文件哈希，明确区分证据写入与修复写入。
5. macro/mixed 共用一个独立测试方法及 `subTest`，各含两个缺失头文件，完整测试总数保持为 12。分别检查变量声明和目标声明，保留变量引用与 recipe 字节。
6. 对真实生成的候选执行 `git apply --check`，实际应用仅在临时隔离副本；原样例初始工作区必须干净，生成后和验证后文件及 Git 状态保持一致。
7. B3 不重复生成 B2 的正确正式候选：该交付已由 B2 完成，B3 的正式目标是证明异常不能到达生成环节。风格测试中的临时候选仅用于测试并自动清理。

## 结果与范围

服务器证据记录五项准确拒绝、无 Patch、源和修复输出不变，完整测试 12 项通过。代价是保存输入和两份源哈希清单；收益是错误码及无修复写入可独立审计。E11 使用 fixed-md，真实 A/B 产物交换留待 E12，不将当前证据解释为跨组联调。
