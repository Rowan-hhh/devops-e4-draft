# 验收与排错

## 提交

|项目|交付内容|通过条件|
|---|---|---|
|部署|Compose、服务状态、实际镜像标识|业务入口与下游能正常调用|
|观测|采集目标、面板截图或导出、任务日志|能按同一任务定位故障，面板保留三个阶段|
|容错|正常、停机、恢复的 `work/` 结果和时间|停机后任务有终态与错误码，恢复后任务成功|
|集成|真实提交 SHA、任务请求、报告、Patch 和重检结果|同一任务贯通各阶段，修复通过并消除原有 MD|
|回滚|补丁拒绝记录和原仓库状态对照|验证失败时原仓库保持原样|

将实验记录、配置和日志整理为一个提交目录。登录密码、密钥和 `.env` 留在服务器。样例与本组项目分别填写结果。

## 排错

|现象|检查|
|---|---|
|首次启动卡在镜像下载|执行 `docker compose pull` 查看哪个镜像拉取失败，按本组镜像源配置处理|
|端口被占用|修改 `.env` 里对应的 `LAB_*_PORT`，同时调整 SSH 转发端口|
|容器运行但 API 无响应|执行 `docker compose ps` 和 `docker compose logs api worker`，核对健康检查和依赖地址|
|Prometheus 显示目标 `DOWN`|确认服务已启动，抓取地址使用 Compose 服务名和容器端口，路径是 `/metrics`|
|恢复后面板仍显示 `0`|运行 `python3 scripts/lab.py target 1`，等 Prometheus 抓到新样本后刷新页面|
|请求第二次仍返回旧结果|查看幂等键。相同请求和键对应原任务，新一轮实验应换键|
|E12 验证失败|看对应目录中的 `submitted.json` 和 `status.json`，用任务编号检查 E12 服务日志|
|真实项目提示不支持|检查本组 E12 的目标映射、构建命令和测试条件，完成适配后再提交|
